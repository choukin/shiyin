# 广告位规范

> 对应 Ardot 设计稿第 08 屏。广告位始终为本地占位，不接任何广告 SDK、不因广告请求网络。
> 注：二期 04 链接下载引入了 `INTERNET` 权限，但只用于用户显式粘贴的媒体直链，与广告无关。

## 1. 决策

| 项 | 结论 |
|---|---|
| 开屏 | **只做品牌 1.2s，零广告**。理由：停留过短无有效曝光、易误触、有合规风险 |
| 条形广告位 | 移到**曲库首页（02 屏）「快捷工具」与「最近添加」之间** |
| 形态 | 可关闭（关闭态持久化到 DataStore）+ 必须带「广告」标识 |
| 编辑类页面 | 04 链接下载 / 05 音乐裁剪 / 06 视频提取音频 **零广告**（导航层 `AD_FREE_ROUTES` 统一断言） |
| 实现 | 本地可关闭占位条，**不引任何广告 SDK、不请求任何广告网络**；`INTERNET` 由二期 04 直链下载引入，广告链路不使用 |

## 2. 落地要求

1. 位置严格位于 02 屏「快捷工具」区块之后、「最近添加」区块之前。
2. 右上角/左上角提供关闭按钮，点击后写入 DataStore，后续启动不再展示。
3. 必须在视觉上带「广告」文字标识（`R.string.ad_label`）。
4. 05 / 06 / 04 屏不渲染 `AdBannerPlaceholder`——在导航层用 `assertAdFree(route)` 统一约束，而非逐屏判断。
5. 开屏（01 屏）1.2s 后自动进入曲库，期间不渲染任何广告元素。

## 3. 商业化前需评估

- 广告 SDK 会引入隐私政策、Play 广告标识合规要求，与「本地播放器」定位存在张力。
- `INTERNET` 权限已因 04 链接下载存在，接广告 SDK 前需重新审视权限用途声明与隐私政策，单独做合规评审。
- 编辑类页面零广告的约束应继续保持。

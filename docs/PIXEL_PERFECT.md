# 像素级还原：需要什么

> 现状：Ardot 设计稿《拾音 · 单机音乐播放器 App UI》（fileId `746937122612662`）
> 链接需登录、本会话无画布读取工具；本地只有 `docs/DESIGN_NOTES.md` 的文字规格（8 屏结构、
> 5 个色值、2 套字体、4 个圆角、390×844 画布）。
> **文字规格只能做「风格一致」，做不了「像素级」**——缺的是每个元素的坐标与度量。
> 本文列出升级到像素级还原所需的输入、规则、工具与当前差距。

## 1. 五级依赖（缺一级就退化为「看着像」）

| 级别 | 需要什么 | 为什么缺了不行 | 当前状态 |
|---|---|---|---|
| ① 设计源 | Ardot 可编辑稿访问权限，或**逐屏导出**（01–08 每屏一张 390×844 的 PNG/SVG）；矢量素材单独导出 SVG/PDF | 4 列×2 行的整张拼板无法取到单屏精确坐标；截图带缩放与压缩误差 | ❌ 缺。链接需登录，本地无导出文件 |
| ② 标注数据 | 每个元素的 x/y/w/h、外边距/内边距、字号/行高/字重/字距、圆角、色值、**渐变起止色与角度**、阴影、透明度、层级顺序；以及所有状态稿 | 色值和圆角只覆盖「颜色/形状」，不覆盖「位置/尺寸/文字度量」，而像素级还原的核心是坐标与度量 | ⚠️ 只有 5 色值 + 4 圆角 + 2 字体名 + 画布尺寸 |
| ③ 字体与资源 | **Noto Sans SC** 与 **Geist Mono** 的 `.ttf/.otf` 原始文件（含实际使用的字重）、OFL 许可；图标矢量稿；封面/波形/视频预览的渐变参数 | Android 字体度量（ascender/descender、基线、字重渲染）与 Figma/设计工具不同，不装同一字体，文字块必然错位数像素 | ❌ 缺。`res/font/` 为空，`docs/licenses/` 只有待办说明 |
| ④ 工程标尺 | 把标注固化为 token（dp 尺寸、Typography、Shapes、渐变 Brush 参数）；关闭动态色/系统字体缩放干扰；状态栏与安全区策略明确 | 手写魔数会漂移；不固定字体缩放，用户系统设置会让所有文字行高变化，比对永远不过 | ✅ 本轮已落地 `ui/theme/` 五个文件（见第 5 节） |
| ⑤ 验收工具 | 逐屏真机/模拟器截图、dp→px 对齐换算、像素差异统计与 diff 图、容差阈值、多密度设备复核 | 「看起来差不多」不是验收；必须有可重复的量化判据 | ✅ 本轮已落地 `tools/pixel_diff.py` |

## 2. 最小可交付集（务实版本）

不要求完整标注也能做到「接近像素级」，最少给我这三样：

1. **8 张单屏 PNG**，每张严格 390×844（或 1170×2532 @3x），不要整张拼板、不要带标题栏/屏标签；
2. **两个字体文件**（Noto Sans SC 用到的字重 + Geist Mono Regular），连同 OFL 许可原文；
3. **一份关键标注**：每屏的区块间距、卡片高度、字号/行高、渐变起止色与角度。

有这三样，我就能把 `ui/theme/` 的占位 token 换成真实数值、把 8 屏 Compose 布局按坐标搭出来，并用 `pixel_diff.py` 逐屏收敛。

**放文件的目录**（放好告诉我即可）：

```
generated-images/        # 8 张单屏 PNG，命名建议 screen_01.png ... screen_08.png
app/src/main/res/font/   # 字体 .ttf/.otf，文件名小写下划线
docs/licenses/           # 两份 OFL 原文
docs/ANNOTATIONS.md      # 或任意形式的关键标注（截图红线圈注亦可）
```

## 3. 坐标换算规则（390×844 → Android）

设计稿的 390×844 是 **@1x 逻辑像素**，对应 Android 的 **dp**（不是 px）：

| 项 | 规则 |
|---|---|
| 布局尺寸 | 设计稿数值 `N` → `N.dp`（390dp 宽为基准） |
| 真机像素 | `px = dp × density`。例：density=3.0 的设备，390dp = 1170px（正好 @3x 导出图） |
| 截图对齐 | 比对前把设备截图按 `设计稿宽度 / (设备宽px / density)` 缩放到 390 宽，或直接把设计稿放大到设备宽 |
| 状态栏/导航栏 | 设计稿 844 高是否含状态栏必须明确；Android 需显式处理 `WindowInsets`（`enableEdgeToEdge()` 后尤其重要），否则整屏会整体偏移 24–48dp |
| 字体缩放 | 验收设备固定「字体大小=默认」「显示大小=默认」；或用 `fontScale` 锁定，避免系统设置污染比对 |
| 动态色 | 一期 Theme 固定 `lightColorScheme`，**不启用 `dynamicColorScheme`**（Android 12+ 壁纸取色会让色值全变） |
| 圆角 | 卡片 16 / 按钮 14 / 胶囊 36 / 封面 24 dp，已在 `Shape.kt` / `Dimens.kt` 固化 |

**常见坑**：设计工具里的阴影/模糊在 Compose 中没有一一对应参数（Skia 与 CSS 滤镜实现不同），
这类效果只能近似，验收时通常单独列入「允许偏差」白名单。

## 4. 验收流程（可重复）

```bash
# 1. 固定设备到 390dp 宽（示例：1080x2400 @2.75 之类设备需换算，优先用 density=3.0 的 1170px 宽设备）
adb shell wm density 480 && adb shell wm size 1170x2532   # 仅在测试设备上执行，记得事后 reset

# 2. 逐屏截图
adb exec-out screencap -p > /tmp/shiyin/screen_02.png

# 3. 对齐 + 差异统计（把设计稿放到 generated-images/）
python3 tools/pixel_diff.py \
  --design generated-images/screen_02.png \
  --capture /tmp/shiyin/screen_02.png \
  --tolerance 8 --output /tmp/shiyin/diff_02.png
```

判据建议（可按屏调整）：

| 指标 | 目标 |
|---|---|
| 平均绝对误差（MAE，0–255） | ≤ 6 |
| 超容差像素占比（单通道差 > 8） | ≤ 3% |
| 关键元素中心点偏移 | ≤ 2dp |
| 文字块顶/基线偏移 | ≤ 2dp |

阴影、抗锯齿边缘、动态内容（进度、波形、专辑封面）列入白名单，不纳入统计。

## 5. 本轮已推进的部分（不依赖设计稿）

| 文件 | 作用 |
|---|---|
| `ui/theme/Color.kt` | 5 个设计色值固化为唯一来源，与 `res/values/colors.xml` 一致 |
| `ui/theme/Dimens.kt` | 390×844 基准 + 4 个圆角常量；其余尺寸**留空待标注**，不臆造数值 |
| `ui/theme/Shape.kt` | `Shapes` 三级圆角 + 胶囊形状 |
| `ui/theme/Type.kt` | Sans/Mono 分工；字体文件未到位时系统字体兜底，字号/行高保持 Material3 默认并标注「待标注」 |
| `ui/theme/Theme.kt` | 固定 `lightColorScheme`，禁用动态色，注入上述 token |
| `MainActivity.kt` | 接入 `ShiyinTheme`，主背景取 `#F5F6F3`（卡片才用白色） |
| `tools/pixel_diff.py` | 设计稿 ↔ 截图对齐与差异统计，输出 diff 图与量化指标 |

> 刻意**不臆造**：设计稿没给间距、字号、行高、渐变角度，这些 token 一律留 `TODO`，
> 否则「填了假数值」比「留空」更危险——它会让后续比对把错的值当成基线。

## 6. 当前差距与阻塞项

| 阻塞项 | 影响 | 谁能解 |
|---|---|---|
| Ardot 画布读不到（需登录，无 MCP 工具） | 无法取逐屏导出与自动标注 | 你导出 PNG/SVG，或提供可访问的分享/只读链接与登录态 |
| 无字体文件 | 文字块必然错位，无法做像素比对 | 你下载官方字体与 OFL 原文放入 `res/font/` |
| 无间距/字号/渐变标注 | 布局只能按风格近似 | 你补标注，或允许我用导出的 PNG 反推（精度有限，需你确认） |
| 本机无 Android SDK / Gradle | 无法编译、无法出真机截图，⑤ 验收链路只能等你侧完成 | 你在 Android Studio 完成 Sync + 安装到设备 |
| 无 git 仓库 | 视觉迭代缺少版本基线 | 需要的话我来初始化 |
